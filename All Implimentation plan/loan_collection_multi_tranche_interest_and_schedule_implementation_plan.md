#### 🔍 मूळ तांत्रिक कारणे (Root Causes in Source Code):
1. **बनावट 'Paid' मुद्दल गृहीतक (`LoanScheduleGenerator.cs` - Line 244):**
   ```csharp
   decimal totalPrincipalPaid = (account.SanctionedAmount > account.PrincipalBalance && account.PrincipalBalance > 0)
       ? (account.SanctionedAmount - account.PrincipalBalance)
       : 0;
   ```
   पहिला टप्पा (₹७०,०००) वाटप झाल्यावर मंजूर मर्यादा (₹१,००,०००) व मुद्दल शिल्लक (₹७०,०००) यातील फरक `₹३०,०००` ला सिस्टीमने **"ग्राहकाने भरलेले मुद्दल"** समजले! त्यामुळे हप्ते १ ते ७ आपोआप `Status = 'Paid'` झाले, जरी ग्राहकाने १ रुपयाही भरला नव्हता!
2. **टप्पा २ वाटपावेळी अर्धवट क्लिनअप (`LoanDisbursementsController.cs` - Line 249):**
   ```csharp
   var oldPendingSchedules = await _context.LoanInstallmentSchedules
       .Where(s => s.LoanAccountID == existingLoanAcc.LoanAccountID && s.Status != "Paid")
       .ToListAsync();
   _context.LoanInstallmentSchedules.RemoveRange(oldPendingSchedules);
   ```
   टप्पा २ (₹३०,०००) वाटप होताना सिस्टीमने फक्त `Status != 'Paid'` हप्ते डिलीट केले, पण वरील बगमुळे जे १ ते ७ हप्ते बनावट 'Paid' झाले होते ते डेटाबेसमध्ये शिल्लक राहिले. त्यानंतर नव्याने २४ हप्ते जनरेट झाले, ज्यामुळे **७ जुने + २४ नवीन = ३१ हप्ते** झाले!
3. **बहु-टप्पा व्याज गळती (`LoanDisbursementsController.cs` Line 238 व `LoanCollectionMaster.tsx`):**
   टप्पा २ वाटप होताच खात्याची `LoanDisbursementDate` थेट `05/05/2026` झाली. परिणामी 01/04/2026 ते 05/05/2026 (३४ दिवस) या कालावधीतील ₹७०,००० वरील व्याज (₹६५२.०५) सिस्टीमच्या गणितातून पूर्णपणे वगळले गेले!

### 🎯 २. प्रस्तावित उपाययोजना व तांत्रिक आर्किटेक्चर (Proposed Solution)

#### सुधारणा १: टप्पानिहाय भारित व्याज गणना इंजिन (Weighted Pro-Rata Multi-Tranche Interest)
कर्जावर एकापेक्षा जास्त टप्पे वाटप झाले असल्यास, व्याज आकारणी एकाच तारखेवरून न करता **प्रत्येक टप्प्याच्या कालावधीनुसार (Segment-Wise)** होईल:
* **कालावधी अ (01/04/2026 ते 05/05/2026 = 34 दिवस):**
  $$\text{व्याज १} = \frac{70,000 \times 10\% \times 34}{36,500} = \mathbf{₹ 652.05}$$
* **कालावधी ब (05/05/2026 ते भरणा दिनांक = 55 दिवस):**
  $$\text{व्याज २} = \frac{1,00,000 \times 10\% \times 55}{36,500} = \mathbf{₹ 1,506.85}$$
* **एकूण देय व्याज:** $\mathbf{₹ 652.05 + ₹ 1,506.85 = ₹ 2,158.90 \approx ₹ 2,159.00}$.
* हे कॅल्क्युलेशन बॅकएंड API (`GetAccountDetailsAndSchedule`) आणि फ्रंटएंड (`LoanCollectionMaster.tsx`) दोन्ही ठिकाणी १००% सुसंगत केले जाईल.

#### सुधारणा २: बनावट 'Paid' स्टेटस निर्मूलन व संपूर्ण शेड्युल रि-जनरेशन
* `LoanScheduleGenerator.cs` मध्ये `SanctionedAmount - PrincipalBalance` वरून परस्पर 'Paid' ठरवणे बंद करणे.
* जोपर्यंत `LoanCollections` टेबलमध्ये ग्राहकाचा प्रत्यक्ष भरणा झालेला नाही, तोपर्यंत कोणताही हप्ता 'Paid' होणार नाही.
* पुढील टप्पा वाटप होताना (`LoanDisbursementsController.cs`), जर खात्यावर कोणताही भरणा नसेल तर जुने सर्व शेड्युल्स पूर्णपणे काढून संपूर्ण मंजूर रक्कमेचे (₹१,००,०००) **अचूक २४ हप्ते** नव्याने तयार केले जातील.

#### सुधारणा ३: हप्ता वारंवारता (Frequency) व थकीत हप्ता अचूकता
* जर योजना किंवा अर्जात वारंवारता "त्रैमासिक" असेल तर हप्त्यांच्या तारखा ३-३ महिन्यांनी (उदा. ऑगस्ट, नोव्हेंबर, फेब्रुवारी) पडतील.
* जर वारंवारता "मासिक" असेल तर प्रत्यक्ष वाटप तारखेवरून पहिली हप्ता देय तारीख (उदा. 01/06/2026) ठरवून चालू तारखेपर्यंतचेच योग्य थकीत हप्ते मोजले जातील (अवास्तव ४ हप्ते थकीत दिसणार नाहीत).

#### सुधारणा ४: खाते `L-2026-130` ची डेटाबेस स्वयं-दुरुस्ती (Self-Healing Fix)
* डेटाबेसमधील ३१ हप्त्यांपैकी ७ अनाथ/डुप्लिकेट रेकॉर्ड्स काढून अचूक २४ हप्ते पुनर्संचयित करणे.
* खात्याची मूळ वाटप तारीख `01/04/2026` कायम ठेवून टप्पा १ व टप्पा २ चे व्याज ताळमेळ बसवणे.
