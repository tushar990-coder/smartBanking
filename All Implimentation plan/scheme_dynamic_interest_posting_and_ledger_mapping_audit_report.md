# कोअर बँकिंग सिस्टीम (CBS) तांत्रिक विश्लेषण व ऑडिट अहवाल: योजनानिहाय डायनॅमिक व्याज पोस्टींग व लेजर मॅपिंग
## Technical Audit & Architecture Report: Scheme-Driven Dynamic Interest Posting & Dynamic GL Ledger Reflection

---

### १. कार्यकारी सारांश (Executive Summary)

कोअर बँकिंग सिस्टीममध्ये (CBS) **डेटा एंट्री ऑपरेटरने योजना मास्टरमध्ये (Scheme / Loan Rate Master) जो "व्याज पोस्टींग प्रकार" (Interest Posting Type) निवडला असेल, त्यानुसारच खात्यावर व जनरल लेजरमध्ये (GL Ledger) अचूक प्रतिबिंब उमटले पाहिजे.** 

सध्याच्या प्रणालीचा सखोल कोड ऑडिट (Code Audit) केला असता खालील २ गंभीर तांत्रिक त्रुटी (Architectural Gaps) समोर आल्या आहेत:
1. **डिस्कनेक्ट (Configuration Disconnect):** ऑपरेटरने `LoanRateMaster` मध्ये `InterestPostingType` (उदा. **"कर्जावर"** किंवा **"येणे व्याजावर"**) निवडलेला असला, तरी मासिक/वार्षिक व्याज आकारणी करताना (`LoanInterestPostingMaster.tsx` व `LoanAccountsController.cs`) योजनेमधील तो पर्याय **पूर्णपणे दुर्लक्षित** केला जातो. त्याऐवजी स्क्रीनवरील मॅन्युअल रेडिओ बटणावर अवलंबून पोस्टिंग होते.
2. **हार्ड-कोडेड लेजर अवलंबित्व (Hard-coded String Dependency):** बॅकएंडमध्ये लेजर्स डायनॅमिकली योजनेमधून (`LoanRate.LoanLedgerID`, `LoanRate.ReceivableInterestLedgerID`, इत्यादी) न घेता अनेक ठिकाणी मराठी नावांवरून (उदा. `"१३० कर्जावरील व्याज"`, `"१२ मुदत कर्ज"`, `"थकीत व्याज येणे खाते"`) स्ट्रिंग सर्च करून हार्ड-कोडेड पद्धतीने शोधले जातात. यामुळे जर एखाद्या संस्थेच्या खतावणीत नाव थोडे जरी वेगळे असेल, तर व्हाउचर्स चुकीच्या लेजरला पडतात किंवा सिस्टीम क्रॅश होते.

### ३. सीबीएस हिशोब तत्त्वानुसार लेजर अकाउंटिंग मॅट्रिक्स (Target Accounting Matrix)

ऑपरेटरने योजनेत जो पर्याय निवडला असेल, त्यानुसार बॅकएंड सिस्टीमने खालीलप्रमाणे १००% डायनॅमिक लेजर्सवर व्हाउचर्स पोस्ट केले पाहिजेत:

#### पर्याय १: योजना पोस्टींग प्रकार = "कर्जावर" (Capitalize to Loan / मुद्दलात समाविष्ट)
*लॉजिक:* आकारलेले व्याज मुद्दलात जमा (debit) केले जाते, ज्यामुळे पुढील व्याज वाढीव मुद्दलावर आकारले जाईल.
- **Dr.** संबंधित कर्ज मुद्दल लेजर (`LoanRate.LoanLedgerID`) — [व्याज रक्कम]
- **Cr.** संबंधित कर्ज व्याज उत्पन्न लेजर (`LoanRate.InterestLedgerID`) — [व्याज रक्कम]

#### पर्याय २: योजना पोस्टींग प्रकार = "येणे व्याजावर" (Accrue to Receivable / स्वतंत्र येणे व्याज)
*लॉजिक:* मुद्दल बदलत नाही. व्याज हे स्वतंत्र 'येणे व्याज' शिल्लकेत जमा होते.
- **Dr.** संबंधित कर्ज येणे व्याज लेजर (`LoanRate.ReceivableInterestLedgerID`) — [व्याज रक्कम]
- **Cr.** संबंधित कर्ज व्याज उत्पन्न लेजर (`LoanRate.InterestLedgerID`) — [व्याज रक्कम]

#### पर्याय ३: कर्ज वसुलीच्या वेळी (Loan Collection Waterfall with Dynamic Ledgers)
जेव्हा कर्जदार पैसे भरेल, तेव्हा जमा झालेल्या पैशांची विभागणी खालीलप्रमाणे संबंधित लेजर्सना डायनॅमिक क्रेडिट होईल:
1. **Dr.** रोख / बँक लेजर (`collection.BankAccountLedgerID` किंवा Branch Cash Ledger)
2. **Cr.** जर येणे व्याज वसूल झाले तर ➔ **येणे व्याज लेजर (`LoanRate.ReceivableInterestLedgerID`)**
3. **Cr.** जर मुद्दल वसूल झाली तर ➔ **कर्ज मुद्दल लेजर (`LoanRate.LoanLedgerID`)**
4. **Cr.** जर दंड/थकीत व्याज वसूल झाले तर ➔ **थकीत व्याज लेजर (`LoanRate.OverdueInterestLedgerID`)**

### ४. सिस्टीममध्ये करावयाचे आवश्यक बदल (Detailed Action Plan & Code Changes)

#### अ. योजना मास्टर व्हॅलिडेशन सुधारणा (`LoanRateMaster.tsx` & `LoanRatesController.cs`)
1. **सक्तीचे लेजर व्हॅलिडेशन (Mandatory Dynamic Ledger Check):**
   - योजना सेव्ह करताना:
     - `LoanLedgerID` (मुद्दल खाते) अनिवार्य.
     - `InterestLedgerID` (व्याज उत्पन्न खाते) अनिवार्य.
     - **जर `InterestPostingType == "येणे व्याजावर"` निवडले असेल, तर `ReceivableInterestLedgerID` (येणे व्याज खाते) अनिवार्य करणे.**
   - लेजर निवडल्याशिवाय योजना सेव्ह होऊ नये, जेणेकरून भविष्यात हार्ड-कोडेड फॉलबॅकची गरजच उरणार नाही.

#### ब. व्याज आकारणी बॅकएंड इंजिन (`LoanAccountsController.cs`)
1. **`PreviewInterestPosting` व `PostInterestBatch` मधील बदल:**
   - खात्यांवर लूप फिरवताना प्रत्येक खात्याचा `acc.LoanRate.InterestPostingType` तपासणे:
     ```csharp
     bool isCapitalize = (acc.LoanRate?.InterestPostingType?.Trim() == "कर्जावर") 
         || (acc.LoanRate?.InterestPostingType?.ToLower().Contains("capitalize") == true);
     
     if (isCapitalize) {
         acc.PrincipalBalance += calculatedInterest;
     } else {
         acc.InterestBalance += calculatedInterest;
     }
     ```
2. **योजनानिहाय डायनॅमिक व्हाऊचर निर्मिती (Scheme-Grouped Dynamic Voucher Posting):**
   - सर्व खात्यांची एकत्रित बेरीज करण्याऐवजी, खात्यांना त्यांच्या `LoanRateID` नुसार ग्रुप करणे:
     ```csharp
     var groupedByScheme = activeAccounts.GroupBy(a => a.LoanRate);
     foreach(var schemeGroup in groupedByScheme)
     {
         var rate = schemeGroup.Key;
         decimal schemeTotalInterest = schemeGroup.Sum(x => x.CalculatedInterest);
         
         // 1. Determine Debit Ledger dynamically based on Scheme's Posting Type
         int debitLedgerId = (rate.InterestPostingType == "येणे व्याजावर")
             ? (rate.ReceivableInterestLedgerID ?? 0)
             : (rate.LoanLedgerID ?? 0);
             
         int creditLedgerId = rate.InterestLedgerID ?? 0;
         
         if (debitLedgerId == 0 || creditLedgerId == 0)
         {
             throw new Exception($"योजना '{rate.LoanType}' ला आवश्यक खतावणी लेजर जोडलेले नाहीत.");
         }
         
         // 2. Add dynamic voucher detail entries without any string searching!
         voucherDetails.Add(new VoucherDetail { LedgerID = debitLedgerId, DrCr = "Dr", Amount = schemeTotalInterest });
         voucherDetails.Add(new VoucherDetail { LedgerID = creditLedgerId, DrCr = "Cr", Amount = schemeTotalInterest });
     }
     ```
3. **हार्ड-कोडेड कोड काढून टाकणे:**
   - `"१३० कर्जावरील व्याज"` व `"१२ मुदत कर्ज"` शोधणारे सर्व `FirstOrDefaultAsync` ब्लॉक्स पूर्णपणे काढून टाकणे.

#### क. फ्रंटएंड स्क्रीन सुधारणा (`LoanInterestPostingMaster.tsx`)
1. **ऑटो-डिटेक्ट योजना धोरण (Scheme-Driven UI):**
   - स्क्रीनवरील मॅन्युअल रेडिओ बटणाच्या जागी ३ पर्याय देणे:
     1. 🌟 **योजनेच्या धोरणानुसार स्वयंचलित (As per Scheme Master - शिफारस केलेले)**
     2. जबरदस्तीने सर्वांना मुद्दलामध्ये प्लस करा (Force Capitalize)
     3. जबरदस्तीने सर्वांना स्वतंत्र येणे व्याजात ठेवा (Force Receivable)
2. **प्रिव्ह्यू ग्रिडमध्ये लेजर व प्रकार पारदर्शकता (Transparency in Preview Table):**
   - प्रिव्ह्यू टेबलमध्ये २ नवीन कॉलम्स जोडणे:
     - **पोस्टिंग प्रकार:** [कर्जावर / येणे व्याजावर]
     - **प्रभावित लेजर (Dynamic Ledger):** [योजनेचे मुद्दल लेजर किंवा येणे व्याज लेजरचे नाव]

#### ड. इतर मॉड्यूल्समधील सुसंगतता (FD & Pigmy Modules)
- `FdAccountsController.cs` आणि `PigmyAccountsController.cs` मध्येही अशाच प्रकारे योजनेतील `FdLiabilityLedgerID`, `InterestExpenseLedgerID`, `PigmyLiabilityLedgerID` वापरून सर्व हार्ड-कोडेड मराठी नावांचे फॉलबॅक्स काढून टाकणे.
